## 1. 摘要

优化 FRP、高延迟和低上行带宽环境中的分片上传：提高请求超时、限制页面级总并发、自动重试瞬时错误、将分片流式落盘、去掉每分片全目录扫描，并在完成阶段直接将分片串流到 SMB。

## 2. 背景与问题

优化前存在以下瓶颈：

- Node.js HTTP 请求固定在 120 秒超时，8 MiB 分片在低带宽竞争下容易被终止。
- 最多 3 个文件任务、每个任务 3 个分片，可能形成 9 个并发请求。
- 任一分片瞬时失败会终止同文件其他请求，没有自动重试。
- 服务端先把完整分片读入 `Buffer`，之后才写磁盘。
- 每个分片都递归扫描整个临时目录，且实际写盘处于全局锁内。
- 完成阶段先生成完整的 `assembled.bin`，造成额外整文件读写。

## 3. 目标

- 弱网分片可持续超过 120 秒。
- 整个页面最多 3 个在途分片请求。
- 瞬时网络或服务错误不会立即导致整个文件失败。
- 分片接收内存占用不再与分片大小乘并发数线性增长。
- 半分片不可被断点恢复识别为完成。
- 去掉每分片全盘扫描、全局写盘串行和整文件本地合并。

## 4. 非目标

- 不持久化浏览器 `File` 对象或服务端任务 Map。
- 不引入外部任务数据库或多实例协调。
- 不在缺少真实 NAS 验证时切换 SMB 客户端或移除 legacy provider。
- 本 Spec 不承诺远端最终文件的原子替换。

## 5. 设计

### 5.1 超时

新增 `HTTP_REQUEST_TIMEOUT_MS`，默认 `1800000`（30 分钟），替代固定 120 秒。反向代理和 FRP 的超时仍由部署方独立配置。

### 5.2 并发控制

保留最多 3 个文件任务并行运行，但所有任务共享一个页面级分片信号量，最多允许 3 个实际请求。等待槽位时可以被取消；重试退避期间释放槽位。

### 5.3 重试策略

每个分片最多尝试 3 次，退避基数为 800 ms。以下错误可重试：

- 没有 HTTP 状态的网络错误。
- HTTP 408、425、429。
- HTTP 5xx。

用户取消、AbortError、认证失败和确定性的 4xx 不重试。重试耗尽后终止该文件其他在途请求，保留已完成 `.part` 供用户再次尝试。

### 5.4 流式分片落盘

请求体通过 Transform 统计字节并直接写入随机 `.uploading` 文件。只有实际大小与该分片期望大小完全一致时，才原子重命名为 `{index}.part`。断流、超长或任务状态变化都会删除临时文件。

### 5.5 临时容量

服务启动时扫描一次临时目录。运行期间接收前按期望大小预留容量，成功提交后扣除被替换旧分片，失败后释放预留。锁只保护容量和任务状态，不覆盖网络接收、磁盘写入或文件校验。

### 5.6 完成阶段

完成前检查分片编号连续、每片大小正确且总大小匹配。随后按顺序读取 `.part`，通过单个 SMB write stream 写入最终路径；成功后清理本地任务目录。不再生成 `assembled.bin`。

## 6. 安全与失败处理

- 上传 ID、任务 owner、文件名和分片索引继续进行严格校验。
- 同一任务的同一分片不能并行写入。
- 服务启动时删除遗留 `.uploading` 和旧版 `assembled.bin`。
- SMB 完成失败时保留本地 `.part`，任务可以再次执行完成阶段。
- 日志和错误不得包含 Cookie、SMB 密码或完整凭据。

## 8. 发布与回滚

发布前设置适合链路的 `HTTP_REQUEST_TIMEOUT_MS`，同时检查 FRP 和反向代理超时。观察上传失败率、临时目录占用和 NAS 写入错误。

若真实 NAS 出现分片生成器与 SMB 客户端不兼容，可回滚完成阶段为本地合并文件后调用 `writeLocalFile()`；不得回滚流式分片接收、任务归属校验或路径安全限制。
